LanePulse: offline install and update
=======================================================

This folder contains everything the workstation needs. Nothing is downloaded during install or use.

Easiest: the setup wizard (Windows)
- Run the single LanePulse-Setup-<version>.exe and choose the install, data and backup folders.
  No administrator rights are needed, Python is included, nothing is downloaded. No account or sign-in is needed.
- It runs the same install.ps1 as below, so the checks, the backup before an update and the automatic start
  are the same. The installer's own output is in <install folder>\logs\install.log.
- Open LanePulse with the LanePulse icon on the desktop or in the Start menu. It starts the server if it is not
  running and opens http://127.0.0.1:8765 in the browser.
- Running Setup again repairs the install (same version, the previous build is kept) or updates it; the data is kept.
- Uninstall from Windows Settings > Apps. That removes the program and the Python it installed; the data and
  backup folders are kept, so installing again picks up the same missions.

Install or update by hand (Windows)
1. Copy this whole folder to the workstation (USB or internal share).
2. Open PowerShell in this folder and run:
     powershell -ExecutionPolicy Bypass -File install.ps1 -Target C:\TrafficWorkbench -Data D:\TrafficData -BackupDir E:\TrafficBackups
   - Python must be installed, or put the official python-3.x.y-amd64.exe installer in this folder first.
   - The installer checks every file against SHA256SUMS, installs into C:\TrafficWorkbench\app-<version>,
     adds the model packs, runs a disconnected install-to-export check, backs up the data (on an update),
     and only then switches start.cmd to the new version.
3. The installer starts LanePulse now. To start it later, run C:\TrafficWorkbench\start.cmd.
   Open http://127.0.0.1:8765 on the workstation. No account or sign-in is needed.

Automatic start (C:\TrafficWorkbench\autostart.ps1)
- Status:   powershell -ExecutionPolicy Bypass -File C:\TrafficWorkbench\autostart.ps1 -Mode status
- User session: -Mode signin   starts when the Windows user session opens, in a minimised window, and restarts the server 10 s after
            it stops. No administrator rights. The output goes to C:\TrafficWorkbench\logs\server.log
            (kept to about 10 MB, with one older file). This is Windows auto-start; LanePulse has no app sign-in.
- Restart:  -Mode restart  e.g. after changing start.cmd. An update does this by itself.
- Remove:   -Mode remove   removes the automatic start and stops the server.
- Power-on: -Mode boot     for an IT administrator only: a scheduled task that starts the server when the
            computer starts, before anyone signs in. Creating it needs administrator rights; the server then runs
            as the Windows account given (asked for its password), which must be able to read the source folders.
            -System runs it as the SYSTEM account, which cannot read network shares.
- Stopping the server stops processing at once. It continues from where it stopped at the next start.

Roll back an update
1. Stop the server.
2. Open C:\TrafficWorkbench\previous.txt: it names the previous version's folder. Edit start.cmd to use that folder.
3. If the update changed the database format, restore the backup taken just before the update into a new folder
   and point start.cmd's --data at it:
     <previous folder>\Scripts\trafficwb-admin.exe verify E:\TrafficBackups\twb-backup-<time>
     <previous folder>\Scripts\trafficwb-admin.exe restore E:\TrafficBackups\twb-backup-<time> --data D:\TrafficData-restored
   Each mission database also keeps an automatic copy from just before each format change, in its backups folder.

Backups
- With -BackupDir, the server backs up every database each night at 02:00 (change with --backup-at in start.cmd).
- "Back up now" is on the missions page. trafficwb-admin backup / verify / restore work from the command line.
- Crops and clips are not in the nightly backup; use trafficwb-admin backup --with-evidence for a full copy.

Speed check
- Double-click C:\TrafficWorkbench\speed-check.cmd. It times the models on every backend this computer offers
  (NVIDIA CUDA, DirectML, CPU) and says which is fastest, how many images a day that is, and how long an hour
  of video takes. The report is saved in C:\TrafficWorkbench\logs\speed-check.txt. Nothing is changed.
- For a truer figure, give it about 20 typical images:
     C:\TrafficWorkbench\speed-check.cmd --images "D:\Feeds\CAM1"

GPU
- A bundle built with --ort auto carries both GPU builds of ONNX Runtime. The installer reads the NVIDIA driver version
  (nvidia-smi): 580 or later gets CUDA, otherwise DirectML. If CUDA does not start in the install check, it switches to
  DirectML by itself. Force a build with -Ort cuda, -Ort directml or -Ort cpu.
- Models run on an NVIDIA GPU when the CUDA build and a suitable driver are present, else on DirectML,
  else on the CPU. The missions page shows which is in use and why. Set TWB_ACCELERATOR=cpu in start.cmd to force the CPU.
